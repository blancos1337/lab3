## 3. Ход выполнения работы

### 3.1. Создание проекта и организация структуры

Создан Android-проект `ProfileApp` с использованием Jetpack Compose. Исходный код разделён на логические части: модель пользователя, главный экран и переиспользуемые UI-компоненты. Такое разделение упрощает чтение, поддержку и дальнейшее расширение приложения.

Основные файлы проекта:

- `MainActivity.kt` — точка входа в приложение, установка Compose-контента и управление выбранной темой.
- `data/User.kt` — модель данных пользователя.
- `ui/ProfileScreen.kt` — основной экран профиля и логика состояния.
- `ui/components/Avatar.kt` — круглый аватар.
- `ui/components/ProfileInfo.kt` — имя, статус и число подписчиков.
- `ui/components/ActionButtons.kt` — кнопки подписки и сброса.
- `ui/theme/Theme.kt` — светлая и тёмная цветовые схемы.

### 3.2. Создание модели пользователя

Для хранения исходных данных создана `data class User`. Она содержит имя, фамилию, статус, число подписчиков и признак подписки. Значения по умолчанию позволяют создать демонстрационный профиль без передачи дополнительных параметров.

### 3.3. Разработка аватара

Аватар реализован с помощью `Box` и `Icon`. Для контейнера использованы `Modifier.size(120.dp)`, `clip(CircleShape)` и фоновый цвет из `MaterialTheme.colorScheme`. Иконка человека выравнивается по центру через `contentAlignment = Alignment.Center`.

### 3.4. Отображение информации профиля

Компонент `ProfileInfo` размещает элементы вертикально с помощью `Column`. Полное имя отображается крупным полужирным текстом, статус — вторичным цветом, а число подписчиков — отдельной строкой. Данные компонента поступают через параметры функции.

### 3.5. Реализация интерактивности

В `ProfileScreen` созданы состояния для признака подписки, количества подписчиков, счётчика нажатий и редактируемого имени. Для сохранения состояния при рекомпозиции применяются `remember` и `mutableStateOf` / `mutableIntStateOf`.

- При нажатии на кнопку подписки состояние меняется на противоположное.
- При подписке количество подписчиков увеличивается на единицу, при отписке уменьшается на единицу.
- `TextField` позволяет редактировать имя непосредственно на экране.
- Кнопка «Сбросить» возвращает исходное имя и фамилию.
- Кнопка «+» увеличивает счётчик нажатий.

### 3.6. Анимация и переключение темы

Для дополнительного задания применены `animateColorAsState` и `animateFloatAsState`: при изменении состояния подписки плавно меняются цвет и масштаб кнопки. Переключатель `Switch` меняет булево состояние темы, после чего `ProfileTheme` выбирает светлую или тёмную цветовую схему Material 3.

### 3.7. Предпросмотр компонентов

Для основных визуальных компонентов и экранов добавлены функции с аннотацией `@Preview`. Они позволяют просматривать интерфейс в редакторе Android Studio без запуска приложения на эмуляторе.

## 5. Контрольные вопросы

### 1. Что такое Jetpack Compose и в чём его отличие от XML-вёрстки?

Jetpack Compose — современный декларативный UI-инструментарий Android, в котором интерфейс описывается функциями на Kotlin. В традиционном подходе XML задаёт структуру разметки отдельно от Kotlin-кода, а затем элементы обычно связываются с кодом Activity или Fragment. В Compose интерфейс строится непосредственно Kotlin-функциями, а при изменении состояния нужные части интерфейса автоматически обновляются.

### 2. Что такое `@Composable`-функция?

Это функция, помеченная аннотацией `@Composable`, которая может описывать часть пользовательского интерфейса или выполнять композицию других composable-функций. Например, `Text()` отображает текст, а `ProfileScreen()` собирает несколько компонентов в один экран.

### 3. Что такое `Modifier`? Приведите примеры его использования.

`Modifier` — объект, с помощью которого настраиваются размер, отступы, расположение, фон, форма, обработка кликов и другие свойства элемента. В работе применялись, например, `Modifier.padding(16.dp)`, `Modifier.fillMaxSize()`, `Modifier.fillMaxWidth()`, `Modifier.size(120.dp)` и `Modifier.clip(CircleShape)`.

### 4. Как управлять состоянием в Compose? Что такое `remember`?

Состояние можно хранить в объектах `State`, создаваемых, например, через `mutableStateOf`. `remember` сохраняет значение между рекомпозициями в пределах текущей композиции. Когда значение состояния меняется, Compose понимает, что связанные с ним участки интерфейса необходимо обновить.

### 5. Как работает рекомпозиция в Compose?

Рекомпозиция — повторный вызов composable-функций для обновления интерфейса после изменения используемых ими состояний или входных параметров. Compose старается пересчитать только те участки дерева интерфейса, которые зависят от изменившихся данных.

### 6. В чём разница между `Column` и `Row`?

`Column` располагает дочерние элементы вертикально, один под другим. `Row` располагает их горизонтально, в одну строку. Для управления выравниванием и расстоянием между элементами используются параметры `horizontalAlignment`, `verticalArrangement`, `verticalAlignment` и `horizontalArrangement`.

### 7. Как использовать `TextField` в Compose?

`TextField` — поле ввода текста. Для него задаются `value`, содержащее текущее значение, и `onValueChange`, callback, который получает новый текст при вводе. Обычно значение хранится в состоянии, например `var name by remember { mutableStateOf("") }`, а затем передаётся в `TextField`.

### 8. Что такое `Divider` и для чего он нужен?

Разделитель — визуальная линия между группами элементов интерфейса. В Material 3 используется компонент `HorizontalDivider()`. Он помогает отделить информационную часть экрана от элементов управления.

### 9. Для чего нужна аннотация `@Preview`?

`@Preview` позволяет Android Studio отобразить composable-функцию в окне предварительного просмотра. Это помогает оценивать внешний вид интерфейса без запуска приложения на эмуляторе или физическом устройстве.

### 10. Как вынести повторяющийся код в отдельный компонент?

Повторяющуюся или логически самостоятельную часть интерфейса следует оформить отдельной `@Composable`-функцией с параметрами для данных, callback-функций и `Modifier`. Например, в проекте аватар, блок информации и кнопки вынесены в отдельные функции и файлы. Такой подход повышает повторное использование и упрощает тестирование и сопровождение кода.
