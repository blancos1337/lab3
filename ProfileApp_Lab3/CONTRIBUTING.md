# Правила внесения изменений

1. Создавайте отдельную ветку для каждой доработки.
2. Старайтесь придерживаться Kotlin coding conventions.
3. Для новых Compose-компонентов добавляйте KDoc и Preview.
4. Для вспомогательной логики добавляйте unit-тесты.
5. Перед Pull Request проверьте проект через Gradle Sync и запустите тесты.
6. В описании Pull Request укажите цель изменения и способ проверки.

Изменения должны сохранять учебную направленность проекта и не добавлять
необязательные разрешения Android без необходимости.
